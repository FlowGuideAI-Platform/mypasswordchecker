Anti-abuse, by design

A key only works where you verified it.

A password-scoring API is a phishing kit if it answers anyone. Ours doesn't: every key is locked to the domains and IP addresses you prove you control, so a leaked or resold key cannot quietly harvest passwords from anywhere else.

Domain verification
Prove the domain, then call from it
Add a DNS TXT record at _mypasswordchecker or serve a token at /.well-known/mypasswordchecker-verification.txt. Takes 2–3 minutes in the dashboard.
IP allowlist
Server-side? Pin your IPs
Backend integrations can verify fixed IP addresses instead — same flow, same dashboard, same rule: requests from anywhere else are refused.
Enforced, not advisory
Unverified means refused
Keys start disabled until their first verified origin. Rotation is one click, and abuse monitoring can suspend a key server-side.

One POST from your verified origin. Score at registration, at password change, or in a security dashboard.

curl
curl -X POST https://mypasswordchecker.com/api/v1/check-password \
  -H "Content-Type: application/json" \
  -H "X-API-Key: mpc_your_key_here" \
  -d '{"password": "candidate-password"}'
JavaScript
